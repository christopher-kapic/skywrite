---
name: skywrite
description: Understand local media, synchronize recordings with offset and drift, create validated assembly edits, and export or render them through the Rust Skywrite CLI.
---

Use installed `skywrite` (or the repository's `target/release/skywrite`). Start with `skywrite doctor` and `skywrite schema`. Successful commands return JSON. Progress/errors go to stderr and failures exit nonzero. Record ALL frustrations with `skywrite nit "description"`; when something cannot be decoded or verified, include the raw command output, the operator-confirmed settings, and the relevant source file from https://github.com/christopher-kapic/skywrite. Before creative choices (music, B-roll, pacing, color), read the user's saved preferences with `skywrite styles list`/`read`, and ask the user when none apply; do not invent taste rules or save styles on the user's behalf. Discover models with `skywrite models list --task TASK`; inspect capabilities/prices and use `--model`, task environment, or a saved task default. Never assume a current model ID or treat zero generic video prompt prices as free generation.

1. Inspect sources: `skywrite inspect <files...>`. Understand durations, streams, frame rates, and audio availability.
2. Sample visuals without a paid call: `skywrite analyze video.mp4 --local --frames 12 -o analysis.json`. Use your image viewer on the returned JPEG paths. Sparse samples do not reveal every event or exact shot boundary.
3. Get words: `skywrite transcribe source.mp4 -o transcript.json`. This explicitly sends bounded audio to OpenRouter. Honor the user's API budget. Cached exact requests reuse results; do not repeatedly disable the cache.
4. Request optional structured visual analysis: `skywrite analyze source.mp4 --model MODEL --transcript transcript.json --prompt 'Editorial intent' -o understood.json`.
5. Sync each camera to the chosen master: `skywrite sync --reference master.transcript.json --asset camera.transcript.json`. For shared audio without transcribing use media paths and `--method audio`. Check quality, matched span, residuals, and whether drift was measurable. Do not use an ambiguous match automatically.
6. The time mapping is `reference_time = offset_seconds + scale*asset_time`. At reference time `r`, the asset source in point is `(r-offset_seconds)/scale`; its edit speed is `playback_rate=1/scale`. Trim to overlap. Do not confuse speed with duration scale.
7. Write the edit JSON (version 2) from `skywrite schema`, using real sources and complete thoughts. Every clip has an explicit timeline `start`; video track 0 is the bottom layer and upper tracks (B-roll, titles) composite above it. Put continuous dialogue on the bottom track or an audio track, and mute B-roll sound with `"audio":{"volume":0}`. Carry the original transcript into analysis with `--transcript`; use original word starts/ends for audible cuts, never seconds guessed from summaries or uniformly sampled frames. Duration is OUTPUT seconds and source consumption is `duration*speed`. Stills have source_in 0 and speed 1. Use `volume_keyframes` and fades to ride music around dialogue, `opacity`/fades for pictures, `sources[].lut` for a log camera LUT, and `master.limiter_db` to cap the mix. Old version 1 files: `skywrite edit migrate OLD.json --output NEW.json`.
8. `skywrite edit validate edit.json` before exporting/rendering. Read frame-rounding warnings. Keep `source_in` word precision; round output duration outward enough to retain the final word after `duration*speed`. Clips on one track must not overlap. Muted B-roll and intentional J/L cuts can cross words visually while a separate dialogue track continues. `skywrite edit suggest --analysis understood.json --brief 'Intent' --model MODEL -o edit.json` can draft a validated edit, but you still judge its quality. Add repeatable `--transcript words.json` for existing analyses without words; unmatched or conflicting alignments fail. Review advisory audible word-cut warnings on stderr.
8a. Describe pictures with `skywrite describe frames SOURCE --every 30` (survey) and `--around TIME --window 1` (dense, around a candidate cut); results are cached per frame, so passes never pay twice. Use `--cast cast.json` (text appearance descriptions) for advisory who-is-visible hints, never as identification. `skywrite describe video SOURCE --start S --duration 8` reports timed gestures, expressions and shot changes.
8b. Focus in on cuts: around each candidate cut, `skywrite review sheet SOURCE --start S --duration 1 --every 2 -o sheet.jpg` shows consecutive exact frames with source times; view them before choosing B-roll or a cut frame. After rendering, `skywrite review lint edit.json --transcript T.json` reports objective problems (silent visible speaker, repeated or clipped words, sound cut off, beds near dialogue), and `skywrite review cuts edit.json --output-dir NEW_DIR` makes audition clips around every cut. Watch and listen to them; delivery and fit are your judgement, guided by the user's saved styles.
9. Render a low-resolution assembly using the edit canvas and `skywrite edit render edit.json -o preview.mp4`; inspect frames/listen to audio around cuts. Give tracks a `role` (dialogue, music, effects); to check dialogue by transcription under a music bed, render `--roles dialogue` and transcribe that. Iterate the edit JSON, not original media.
10. Deliver `skywrite edit export edit.json --to premiere -o edit.xml` (Premiere Pro), `--to fcpxml -o edit.fcpxml`, `--to ffmpeg -o render.py`, or an optional `--to hyperframes|remotion -o NEW_PROJECT_DIRECTORY`. Optional composition runtimes are only required for those targets. You may extend generated projects with graphics/effects.

Use `skywrite image render --file title.html -o title.png --width 1280 --height 720` for native still graphics using embedded upstream Takumi 2.19.0 and the bundled OFL Geist font. Use inline HTML style/tw attributes or upstream JSON nodes; local image paths resolve relative to the template. Register extra font files with repeated `--font PATH`. No Takumi executable is required. WebP/JPEG support `--quality`; PNG is lossless. Remote resources, SVG, stylesheet blocks, and JavaScript are unsupported. Then add the still to the edit.

Never overwrite an original media file. Existing outputs require `--overwrite`. Do not fabricate word timestamps or claim events outside the observed coverage. Model suggestions are candidate edits, not authoritative shot detection. Preserve source licenses/attribution in any shared fixture or deliverable. No ads capabilities are part of this CLI.

Use `skywrite styles` for reusable creative prompts and `skywrite skills` for procedural instructions. Read built-in workflows before using a new output tool. Shared content-addressed frame and exact contextual-request caches live in the XDG user cache; keep them enabled to avoid duplicate charges. See `skywrite models defaults` for task environment names. Native HTML graphics can use explicit cached Google Fonts with `--google-font FAMILY`; offline rendering uses `--offline`. Compose graphics into edits and inspect character/reference-frame capabilities before generation. Styles/skills are text references, never implicitly executed.

Generation: discover task models before spending. Start a character with `generate image`, reuse it with `--reference`, then animate using `generate video --first-frame` or `--last-frame`. H3 Max accepts one keyframe per request. Save the job ID and use `jobs resume JOB_ID --wait 60 --output video.mp4`. Never automatically resubmit an uncertain job; inspect OpenRouter activity. A new `--take` intentionally spends for a new variation. See [generation workflows](../../docs/generation.md).

AI video enlargement: `upscale video --source-job JOB_ID --model MODEL --factor 2`, or `--source-url` for your hosted HTTPS asset. OpenRouter currently does not accept local MP4 uploads directly; explicit `--upload` can bridge a configured public S3/R2 bucket (live compatibility unverified). `upscale image INPUT --factor 2 --output OUT.png` is non-AI Lanczos resizing. Do not call generative high-resolution editing faithful super-resolution. HTML graphics, generated stills, and video clips can all be combined in one edit.

Local MP4 upscaling may opt into a user-configured public S3/R2 bucket using `upscale video FILE --upload [--delete-upload-after]`. Never enable public access or upload implicitly. `storage upload FILE --dry-run` needs no cloud credentials; `storage purge --dry-run` makes read-only LIST/HEAD requests. See `docs/storage.md`; live bucket compatibility remains user-unverified. Purge selects only marked Skywrite hash objects and normally preserves active local jobs.

Setup: `skywrite init` adds missing offline starter preferences; `skywrite defaults TASK` reports the effective model and source, and `skywrite defaults TASK set MODEL` changes a saved choice. Environment overrides remain effective. Read [configuration](../../docs/configuration.md).

Narration/music: discover `speech-generation` voices or `music-generation` models, then use `generate speech --file script.txt --voice VOICE --model MODEL --output narration.mp3` or `generate music --prompt PROMPT --instrumental --model MODEL --output bed.mp3`. Use actual transcribed word timings for visual synchronization. Read `skywrite skills read technical-explainer` and [audio generation](../../docs/audio-generation.md). These are decoded waveform assets, not MIDI. Never assume zero generic music token prices mean a free song. Completed jobs replay without another paid submission. Share deliverables through `outputs upload/list/download`; see [shared outputs](../../docs/outputs.md).

Captions: deliver SRT by default so the user can edit wording, timing and style in their NLE. Burn captions into pixels or render caption images only when the user explicitly asks. For Premiere, deliver the XML and its SRT together and tell the user to import both.

Dialogue timing: read `skywrite skills read synchronization` for source-time conventions and bounded word lookup. `analyze --local --transcript transcript.json --start SECONDS --duration SECONDS` attaches existing words without an ASR call. Edit suggestions recheck source fingerprints and receive only words overlapping each analyzed range; words crossing a range boundary retain their actual starts/ends. Narrow ranges when the word context limit is exceeded. Listen around every dialogue cut; provider timestamps are alignment evidence, not a guarantee of perfect phoneme boundaries. Missing words do not prove silence. No automatic paid retakes.
